# Agent Frontdesk

**Goal:** The web console is a remote window onto each coding agent's desktop app. It reproduces each desktop app's conversation UI 1:1 and only carries messages to and from the desktop. Execution, history and settings stay in the desktop app. Local data is read-only, and every message the console sends goes in through the desktop app's own channel. Every capability two agents share (parsing, rendering, sending/steering/queuing, the dock and quota) is abstracted once into the plugin contract and the shared kit, so a newly added agent only needs its data adapter and a few variables and never hard-codes anything.

What that sentence implies (details and reasons in `skills/add-desktop-engine/references/philosophy.md`):

- **Desktop app is the source of truth.** Reproduce whatever the desktop shows (worked time, steer bubbles, diagrams, file links); do not invent what it doesn't. Show "completed" or "failed" only with evidence from the native record; when uncertain, say it is being confirmed.
- **A request to restyle or beautify covers the console's own parts only.** Those are the agent rail, the sidebar and chat header, dialogs, and the console's own status lines (the run-state tag and the "cannot send" note above the composer, the error notice, the loading line). Whatever a desktop app draws itself keeps that app's look: a reply's content, tool rows, "Thinking", "Worked for", the step list, the end-of-turn card and its buttons, the composer and the model / effort / permission row under it. Before changing how something in the conversation looks, check which of the two it is.
- **How sending works.** Prefer official channels (SDK, app-server, CLI). Where an official channel can't do what the desktop can (steering a turn the desktop is running, sending as the user), use the desktop app's own mechanism: Claude's accessibility send, Codex's thread-follower IPC. If that fails, fall back (for example to the queue) and say why. Never fall back to a separate CLI process that runs the turn itself: it is a second writer the desktop does not see, which defeats the point. When the desktop can't take a message, don't send it and say why. Never read another program's tokens.
- **The session's own settings follow the message.** Model, reasoning effort and permissions follow that session's desktop settings, and the console's menus start on them. A different pick in the console is made in the desktop app itself before the message is sent, through its own menus (Claude: accessibility) or through the window that holds the session, which changes it as its menu would (Codex: thread-follower IPC), so the desktop shows and keeps it; if the desktop cannot make the change, nothing is sent and the reason is shown. The user takes responsibility for not writing to the same session from two places at once, so do not add read-only modes or locks.
- **Fix by abstraction, not hard-coding.** When one agent shows a problem, first check whether the others have it too, then fix it once in a shared layer (presentation / kit / `markdown()` / RunService). Per-engine differences belong only in the data adapter (`src/server/*-bridge.ts`, `src/server/plugins/`) and skin variables.
- **New agents are onboarded with the `skills/add-desktop-engine` skill.** Contract: `references/plugin-contract.md`. Acceptance checklist: `references/acceptance.md`.

Working conventions: the code is strict TypeScript under `src/` (`src/server`, `src/client`, and the plugin contract both share in `src/shared/contract.ts`); `npm run build` writes `dist/`, and `npm run dev` runs Vite (HMR) plus `tsx watch`. A server-side change (`src/server/`, `src/shared/`, native helpers) takes effect after a rebuild and restart; before restarting an instance someone is using, confirm no web-sent run is in progress (`/api/activity` shows nothing `running`). On macOS only an instance started from a terminal that has the Accessibility permission can drive the Codex and Claude windows; on Windows any instance running with the same rights as the desktop apps can, and each action makes the app's window take the focus for a moment (`docs/windows.md`). A page-only change needs `npm run build` and a page reload. Raw screenshots contain real chats and must not be committed. Run `npm test` and `npm run check` (type check + build) before finishing. Personal conventions (reply language, which port your own instance runs on) go in `CLAUDE.local.md`, which is not committed.
